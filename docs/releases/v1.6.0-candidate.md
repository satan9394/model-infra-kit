## Failure record and release boundaries

The first Phase 2 run exited 1 because the new fixture compared HTTP JSON with
an in-memory tree containing optional `undefined` properties. The assertion now
normalizes the expected tree through JSON serialization; the retry and final
battery passed. Evidence remains in `phase2-battery.log` and
`phase2-battery-retry.log`. No production behavior was changed to pass this check.
Both deliberate battery self-checks returned the expected exit 1: extra/missing
runtime exports and a missing auto artifact are rejected.

The all-day discount ledger fixture avoids wall-clock dependence; fixed UTC
timestamps separately check the wrapping start/end boundaries. Hard caps use
recorded spend, without reservations or cancellation of in-flight requests, and
apply to HTTP dispatch rather than embedded generation. Tree topology requires
retained detail; archived steps cannot be reconstructed. Performance and real
supplier behavior are not certified by this release slice's mock battery.

The task card, board, handover, bounded state and `.tmp/g128/` evidence are local
ignored records under existing repository rules. The release commit includes
only the two manifests, changelog, README, interface document, battery script
and this report. Human approval is required before remote push/CI and publication.
