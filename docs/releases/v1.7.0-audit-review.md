## Limitations and failure accounting

- Observed warmed averages: standard fixture 36.740725µs over 20,000 calls;
  cycle/deep/huge-JSON bypass 2.74799/2.65263/0.61158µs; Unicode 35.205045µs.
  These are measured averages, **not universal <50µs hard bounds**. Arbitrary
  object enumeration, Proxies, executable SDK getters and OS scheduling cannot
  provide such a guarantee. Inputs outside eligibility bypass caching.
- HTTP error bodies are bounded at 64 KiB; SSE complete events at 4 MiB UTF-16
  code units. Complete-event buffering can affect delivery latency. Independent
  UTF-8 雪😀/CRLF event/id/retry/comment/[DONE] probes preserve normal bytes.
- Successful non-error JSON retains its raw provider payload contract. Verification
  establishes masking of tested errors/status paths, not every possible successful
  provider string or every future credential representation.
- Red assertions expose the original defects and are non-vacuous. Missing-provider
  initial fetch fixtures, relative preload failure and two intermediate cache
  compatibility regressions are retained and distinguished from valid red evidence.
  Earlier raw assertion logs have been sanitized with the project redactor and exact
  synthetic-credential replacement.
- Local Windows verification is complete. Cross-platform CI and published npm
  verification remain behind the human push/publish gate; they were not executed.
