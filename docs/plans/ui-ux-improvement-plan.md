# Model Infra Kit — UI/UX 整改与产品体验升级方案

> **文档类型**：UI/UX PRD + 前端实施规范（可供 GitHub Issue、开发 Agent 和设计评审直接使用）  
> **基线**：Model Infra Kit v1.7.0 / 架构图提交 `267628e`；2026-10-12 提供的 Dashboard 截图  
> **范围**：`apps/dashboard` 的 10 个主页面、4 个嵌入式路由、深浅主题与移动端  
> **优先级**：P0 = 正确性或关键体验阻塞；P1 = 高价值工作流；P2 = 进阶便利功能

## 0. 执行摘要与定位

### 0.1 结论

现有 UI 具备一致的开发者工具视觉基调（深色背景、紫色强调、侧边栏、卡片和等宽数据），功能覆盖从接入到计量的多个环节。**不建议整体推翻设计**；应把重点从「静态数据展板」转向「发现问题 → 定位一次请求 → 解释运行时决策 → 处理配置 → 验证结果」的闭环。

产品定位：**Model Infra Kit 是可嵌入宿主应用的模型基础设施运行时；Dashboard 是其可选的管理与可观测控制台，不是核心运行时本身。** UI 的职责是准确表达运行时事实，而不是将配置与展示需求反向耦合进请求执行路径。

### 0.2 设计原则（约束优先级从高到低）

1. **语义正确性 > 图表美观**：成本 `unknown` 不表示 `$0`；逻辑请求与上游尝试分开；失效、未检测、未配置不得混为一谈。
2. **动作导向**：每个异常指标必须有合理的下钻目标和可复制的诊断上下文。
3. **真实数据约束可视化**：没有 `parentSpanId` 不绘制虚假的父子 Span；缺失价格来源时不得推断精确账单。
4. **核心能力低摩擦**：完成首次请求、调试失败、查看成本、修改覆盖价等高频流程尽量减少跨页操作。
5. **复用组件而不复用不合适的页面壳**：完整 Dashboard、Embed 和移动端共享底层组件/数据口径，但有各自适配布局。
6. **克制的视觉语言**：保留现有深/浅主题与紫色品牌色；避免为了“更现代”增加无意义卡片、装饰图表或动画。

### 0.3 成功标准

- 用户从 Overview 的失败指标能够带过滤条件进入 Logs，并打开具体请求的诊断详情。
- 用户可从一次逻辑请求看清最终结果与各次上游尝试；若 API 未提供关联数据，界面不虚构。
- 费用数字有单位、定价来源、准确性等级、缺失/部分覆盖提示；历史归档明细不可用时有明确反馈。
- 供应商的启用、配置完整、连接测试、运行时被动健康各有独立的 UI 状态。
- 390px 移动端不产生页面级横向溢出，日志、价格、模型管理的关键内容与操作不被裁切。
- Embed 在无宿主导航、较窄容器、数据不可用时仍有完整的加载/错误/空态。

## 2. 全局信息架构（IA）与导航

### UI-001 / P0：重构主导航为用户工作域

建议不立即变更既有 URL，仅调整分组、标题与顺序：

```text
MIK Console
├─ 工作台
│  ├─ 概览                   /
│  ├─ 用量与成本             /trends
│  ├─ 请求日志               /logs
│  └─ 调用链路               /traces
├─ 模型基础设施
│  ├─ 供应商                 /providers
│  ├─ 模型目录               /models
│  └─ 价格管理               /pricing
├─ 治理与自动化
│  ├─ 配额与限流             /quotas
│  └─ Webhook 通知          /webhooks
└─ 开发者
   └─ 快速接入与调试         /connect
```

**命名约束**：「智能体任务链路」建议改为「调用链路 / Traces」。Trace 不天然等于 Agent Task；对于普通 SDK 请求同样成立。「趋势」更明确命名为「用量与成本」，但原路由可以保留。

**验收**：桌面/移动导航顺序一致；原链接和深链接正常；嵌入式界面不显示完整导航；键盘 Tab 可以遍历并明确指示当前位置。

### UI-002 / P0：统一顶栏与运行状态

**推荐结构**：左侧为当前应用/作用域与页面标题；右侧按重要性组织「网关连通状态」「数据最近更新时间」「刷新」「主题」「语言」。时间范围、Provider、Model、Status 使用页面共享的过滤条，而不是在每个标题行重复状态徽标。

需要严格区分：

| 信号 | 语义 | 禁止混用 |
|---|---|---|
| Gateway connected | Dashboard 是否可访问网关 API | 不代表每个 Provider 健康 |
| SSE connected | 实时事件通道连接中 | 不代表后台全部数据已经更新 |
| Data freshness | 最近成功刷新与过期情况 | 不等于 RTT |
| Provider connection test | 主动测试结果与检测时间 | 不等于被动熔断状态 |
| Circuit breaker | 运行时被动健康状态 | 不能解释成跨实例全局状态 |
| Budget consumption | 已消费/预算上限 | 未配置预算时不可显示 `0%` |

**验收**：「今日 0% / 本月 0%」若无明确预算分母，应隐藏百分比并显示「未配置预算」；SSE 断开与 API 不可达有独立反馈；多实例运行时不能把局部健康状态标成“全局健康”。

### UI-003 / P0：共享过滤器与 URL 状态

过滤器建议规范为：`appId`、`from`、`to`、`provider`、`model`、`status`，以 URL Query 表达可共享的视图状态。具体字段及命名应在接口契约核对后确定。

- Overview/Trends/Logs/Traces 使用相同区间定义和时区提示；若跨页不支持完全相同的过滤项，要明确降级规则。
- 点击概览失败数 → Logs，自动带入原时间范围和 `status=error`（以最终统一状态词汇为准）。
- 点击模型成本排行 → 该模型筛选视图。
- 页面刷新/返回后仍保留筛选；点击「重置」可恢复默认区间。
- `Today`、`7d`、`30d` 是快捷选项，必须显示对应实际起止日期；区分闭区间/半开区间和时区。

**验收**：深链接可复现；不同页面对同一过滤条件显示一致统计分母；日期边界 E2E 包括本地午夜、跨月、DST（若支持相应时区）。

## 3. 统一视觉与组件系统

### UI-004 / P0：设计 Token 与布局

建议建立语义 Token（以下为**目标规范**，非宣称现有值）：

| 类别 | 建议 |
|---|---|
| 字体 | 页面标题 24–28px；卡片标题 15–16px；正文 14px；高频辅助文字尽量不低于 12px |
| 间距 | 4/8px 系列，核心节奏 8/12/16/24/32px |
| 主色 | 紫色只用于主要 CTA、聚焦、选中、重点指标，不承担所有状态颜色 |
| 状态色 | Success / Warning / Danger / Neutral 采用语义命名，并具备非颜色识别渠道 |
| 容器 | 统一圆角、描边和悬停/聚焦行为；优先密度适中、避免多层卡片套叠 |
| 代码字体 | 仅代码、模型 ID、Request ID、金额等使用等宽字体 |
| 图表 | 共用 Tooltip、轴标签、单位、图例、空数据、加载和错误组件 |
| 表格 | 同一套行高、数字右对齐、排序、固定表头、移动端降级规则 |
| 主题 | Dark/Light 同一语义 token，两主题分别做对比度审查 |

建议将组件组织为 `AppShell`、`StatusIndicator`、`FilterBar`、`MetricCard`、`DataState`、`CostValue`、`UsageTokenBreakdown`、`DataTable`、`RequestDetailDrawer`、`TraceTimeline`、`SourceBadge`、`ConfirmChangeDialog` 等。目录名由实际仓库约定确定，不强制重新命名现有组件。

**验收**：页面只消费语义 Token；极小金额显示保留有效精度，完整微美元展示在详情；加载中/无数据/无权限/网络失败不共享同一个空白容器；交互元素支持键盘可见焦点。

### UI-005 / P1：空态组件标准

不同空态须区分：

1. **首次未配置**：说明需配置什么、如何配置、到哪里配置；只读部署给出 CLI/config 引导。
2. **已配置但无数据**：提示当前筛选无结果，并允许清除过滤器。
3. **无权限**：说明此操作需要的权限等级，不伪装成“无数据”。
4. **数据已归档**：说明仅有聚合记录，单次请求不可恢复。
5. **暂时不可用**：提供重试与错误上下文，不隐藏为 0。

## 4. 逐页面整改清单

### 4.1 Overview `/`（UI-101 / P0）

**现状证据**：费用区间、请求量、Token、成本曲线、缓存比率、平均/首 Token 延迟、Provider/Model 用量表。宽屏 30 天图表有显著空白；成本金额保留过多小数；「今日/月度百分比」重复出现且分母不清。

**目标首屏**：

```text
[App / Scope] [日期范围] [Provider] [Model] [状态]
[成本（带确切/估算/未知信息）] [逻辑请求] [最终成功率] [Token 总量]
[成本趋势（主图）]                [运行表现（次级卡）]
[异常和慢请求入口]
[供应商成本排行] [模型成本排行]
```

**任务**：
- 费用区间统一通过 `CostValue` 展示「精确 / 估算 / 区间 / 未知」语义；`$0` 只用于确认零费用。
- 请区分「逻辑请求数」「上游尝试数」；已有 API 不支持时先标注目前统计口径，不应先改前端文案误导。
- 「本地响应缓存命中」和「上游 Prompt Cache Token 占比」分别命名并提供公式。
- 图表使用真实数据点，不进行易产生误读的曲线过度平滑；尽量使用不引入虚构极值的连接方式。
- 指标卡/排行可点击下钻；优先支持失败日志、模型耗费、慢请求。
- 趋势图高度不因邻栏 KPI 卡片而无谓拉长；按内容自适应。

**验收**：费用缺失时不会默认为 0；图表 Tooltips 的日期/金额与 API 一致；用户最多两次点击从“失败率”到目标请求详情；空数据首屏不渲染假的曲线。

### 4.2 Trends `/trends`（UI-102 / P0）

**现状证据**：同图呈现 Input、Output、Cache Read、Cache Write 与 USD Cost，属于不同维度并置；Token 图层是否互斥仍需 API 验证。

**任务**：
- 采用两个图层/Tab：「Token 构成」与「成本」；只有具有互斥、可加性定义的 Token 类别才能堆叠。
- 若 `cache_read` 已包含在 `input` 中，不得把二者直接堆叠成输入总量。
- 成本图明确按天聚合的区间边界；区间金额采用上下界带或分列展现。
- 每日表格增加排序、单位提示、复制/导出当前视图（导出可以 P2）；点击日期跳转 Logs。
- 缺失日与 0 请求日要分离，不使用插值伪造数据。

**验收**：图表加总与明细表通过同一聚合口径对账；未定价部分可见；关闭某图层后轴/图例不产生错误单位。

### 4.3 Logs `/logs`（UI-103 / P0）

**目标**：从只读分页表升级为请求诊断入口。

**推荐结构**：`快捷筛选 (失败/慢请求/高成本/重试)` → `可排序列表` → `右侧 RequestDetail Drawer`。

**Drawer 分区**：Summary、Attempts、Routing、Usage & Pricing、Trace Link、Error。若后端尚缺关联信息，则该区明确显示“当前数据不可用”，不得推断轮换路径。

**列表默认列**：时间、模型/供应商、最终状态、耗时、Token、成本、Request ID；高级列支持 `traceId`、错误码、fallback 标记和价格来源（以前端 API 实际字段为准）。

**交互与保护**：
- 长 ID 缩写显示、完整复制；复制错误详情时对敏感值脱敏。
- 支持 URL 保留过滤器和分页；限制一次最大分页大小，避免长表性能下降。
- 状态词汇区分 User Request 最终状态与 Attempt 状态。
- `requestId` → Drawer，`traceId` → Traces，`provider/model` → 对应资源或筛选视图。

**验收**：失效/失败状态、超时、限流、重试等诊断信息不互相覆盖；点击/键盘可以打开/关闭 Drawer；详情无权限时不泄露数据。

### 4.4 Traces `/traces`（UI-104 / P0）

**命名**：建议 UI 名称从「智能体任务链路」调整为「调用链路」，保留 `Trace` / `Session` 视图切换。

**目标**：提供任务汇总与选中调用的真实时间线，不强制引入 Agent 专属抽象。

**任务**：
- 左栏可选 Trace 列表增加状态、总耗时、调用次数、成本区间。
- 点击 Trace → 右侧展示已知 Span/调用时序；有 `parentSpanId` 和时间戳时才绘制层级瀑布。
- 点击单次调用 → 展示 Request ID、提供商、模型、Token、耗时、成本与错误。
- Thinking Token `0` 与未上报/未知使用不同渲染。
- 已归档仅剩聚合数据时，显示「仅保留汇总，明细不可用」，不生成推测的 Span。

**验收**：所有时间线条目都与真实记录关联；选中状态 URL 可定位；空的右侧面板包含可操作的选取提示。

### 4.5 Providers `/providers`（UI-105 / P1）

**任务**：
- 状态分离：配置有效、运行启用、最近主动连接测试、被动熔断健康。
- 提供 Provider 详情展开：协议、Base URL、授权引用是否配置、模型数量、最后测试时间、最近失败。
- `未测试`、`测试失败`、`测试成功` 禁止共用同一“健康”标签。
- 控制台展示的配置来源必须说明是启动配置、运行时状态或持久配置；在 `isolatedProviders: true` 时尤其重要。
- 操作按钮应有等待态和明确的重启/热加载效力说明；敏感字段永不回显明文。

**验收**：开启 Provider 不等于测试通过；配置没有持久化管理 API 时提供配置指引而非假操作。

### 4.6 Models `/models`（UI-106 / P1）

**任务**：
- 保留标准模型事实目录与本地实际端点分离，但将主要工作区收敛为可筛选表格。
- 标准模型能力、上下文长度、输出上限、价格来源与当前可调用性分列。
- 详情 Drawer 展示能力证据来源、上下文、端点、价格版本与“复制模型 ID / 打开 Playground”。
- 能力徽标区分「文档声明」与「实际测试结果」（若有该数据）；不要单凭存在标准目录就标“可用”。
- 自定义/Mock 模型标签准确说明来源，不把测试数据呈现为正式提供商公告。

**验收**：模型筛选结果一致且 URL 可复现；标准目录不存在具体端点时不可一键发起不可用模型请求。

### 4.7 Pricing `/pricing`（UI-107 / P0）

**任务**：
- 改造价格编辑为「选择模型 → 查看目录价/覆盖价/生效价 → 编辑 → 差异确认 → 保存」。
- 展示单位 `USD per 1M tokens`，字段：input/output/cache_read/cache_write；不支持或未知必须保持 `—`，不能误作零价。
- 明确价格优先级为 `pricing_overrides > llm-pricing overrides > 上游目录 > 内置 archive`（据架构图，具体字段合并规则待验证）。
- 操作“撤销”改为“移除手动覆盖 / 恢复目录价”，并提示后续账单与历史已落库账单的区别。
- 管理操作必须具备权限确认、更新中、成功/失败反馈以及并发修改冲突反馈。
- 显示目录的更新时间、来源、是否过期，并在修改前揭示成本影响的适用范围；不得承诺未支持的历史重算。

**验收**：移除覆盖后生效价按真实优先级变化；历史已固化费用不会被 UI 表述为“已重新计价”；无权限用户无法编辑。

### 4.8 Quotas `/quotas`（UI-108 / P1）

**任务**：
- 空态解释组织/应用的层级配额与限流区别、配置来源及下一步命令/管理入口。
- 若 API 支持：展示用量进度、预算周期、阈值、最近阻断、来源作用域；否则先作为只读诊断页。
- 「预算未配置」区别于「已配置预算且用量为 0」。

**验收**：未配置配额不会展示虚假的 0% 消耗；正确提示当前应用、组织层级与刷新周期。

### 4.9 Webhooks `/webhooks`（UI-109 / P1）

**任务**：
- 首次空态展示如何配置投递目标、权限前提、可用事件、发送测试事件前置条件。
- 有记录时展示目标列表与投递记录（待投递/尝试中/重试/成功/失败）；每条记录展示时间、事件种类、重试信息与错误。
- 明确当前 Webhook 是 `best-effort`：文档指出 HMAC、有界重试、**重启丢失内存队列**。不得将其渲染为持久可靠队列。
- 只有未来实现持久 Outbox 后，才加入“持久投递保证”的相关 UI 说明。

**验收**：未配置时测试按钮不可用并给出理由；投递失败可以下钻；UI 可靠性描述与运行时一致。

### 4.10 Connect `/connect`（UI-110 / P0）

**目标**：把“代码示例页”变为“首次成功调用向导”。

建议步骤：

1. 确认本地网关地址、权限与连通性。
2. 选择当前**可调用**的 Provider/Model。
3. 选择 SDK（保留 Vercel AI SDK、OpenAI Node/Python、LangChain Python、cURL）。
4. 生成安全的最小示例，复制并调用；认证采用环境变量而非明文密钥。
5. Playground 发送测试请求，显示响应、延迟、Token、成本、ID；失败时跳转 Logs。

**验收**：从首次打开页面到第一个成功请求有清晰状态反馈；代码与当前选中模型/网关一致；敏感令牌不嵌入生成代码；失败时可复制诊断上下文而不暴露秘密。

## 5. 移动端、Embed 与无障碍

### UI-201 / P0：390px 移动端专项

| 断点 | 建议结构 | 核验重点 |
|---|---|---|
| `<640px` | 抽屉式导航；KPI 1–2 列；复杂表格以摘要卡/详情抽屉展示 | 390px 不裁切模型 ID、价格、操作入口 |
| `640–1023px` | 可折叠侧栏；KPI 2 列；表格允许局部横向滚动 | 无页面级横向滚动 |
| `≥1024px` | 常驻侧栏与完整表格 | 表格密度与图表留白平衡 |

必须覆盖 `/logs`、`/models`、`/pricing`、`/traces`，不能只验证 Overview；详情抽屉在移动端改为全屏 Sheet 并保留返回路径。

### UI-202 / P1：Embed 独立契约

- 继续复用数据组件，但 Embed 不附带全局 Sidebar/页脚。
- 明确容器宽度、自动高度/内滚策略、主题透传、加载/断线状态。
- 若引入 `postMessage` 与宿主通信，规定严格的 `targetOrigin` 校验、允许来源与消息 Schema，避免为嵌入便利弱化安全边界。
- Embed 默认 7 日的现有行为应在界面中明确显示；不同宿主容器可覆盖过滤器时须校验作用域。
- 同一数据在完整页和 Embed 呈现相同单位与成本精确度。

### UI-203 / P1：无障碍与国际化

- 键盘焦点可见；筛选、Dialog、Drawer 具备标签与关闭途径。
- 暗/亮主题正文与辅助文本进行 WCAG 对比度测试（目标 AA，特殊可视化元素单独审计）。
- 图表提供表格或屏幕阅读器摘要，不以颜色单独表示成功/失败。
- 中英文文案采用同一词汇表；错误码保留原始英文码，提供可选本地化释义。
- 动画尊重 `prefers-reduced-motion`。

## 6. 前后端契约依赖与禁止事项

### 6.1 UI 不应越权假设的新能力

| UI 目标 | 需要验证的后端事实 | 缺少时的正确降级 |
|---|---|---|
| 请求 Attempts | 逻辑请求 ID 与每次 Attempt 的映射 | 显示当前记录口径及“尝试详情不可用” |
| Trace 瀑布 | `start/end`、`spanId`、`parentSpanId` 等关系 | 展示真实调用序列或汇总 |
| 成本来源 | `pricing_source`、`pricing_basis`、上下界与历史留存 | 显示“无法确认来源”而非精确账单 |
| 路由诊断 | 被选候选、失败分类、切换原因 | 仅显示实际 Provider/Model，不编造裁决过程 |
| Provider 健康 | 运行时实例级健康信息 | 区分连接测试与被动熔断，不冒充全局状态 |
| 权限操作 | Query / Admin 鉴权和配置持久化行为 | 操作禁用并给配置文档入口 |
| 已归档详情 | 是否保存明细 / 是否可恢复 | 显示保留边界并提供导出/归档信息（若支持） |

### 6.2 明确不做

- 不把 Dashboard 改造为 Agent Workflow 编辑器或聊天式 Agent 产品。
- 不以美观为由重算历史账单、伪造 Trace 层级或混合不可加的 Token 图层。
- 不默认要求 Redis/Kafka/全局分布式状态才能显示控制台。
- 不把测试网关的 mock 模型数据误标成真实生产运行质量。
- 不承诺价格修改将回写历史 usage 事件。

### 8.2 自动化建议

- 继续使用已有 `pnpm --filter @mik/dashboard seed` 的演示数据链路与 Chrome/CDP 截图流程（以实际脚本维护情况为准）。
- 视觉回归固定时间区间、数据种子、主题、视口，避免 SSE 持续更新引起非确定性快照。
- 使用 Playwright E2E 验证：从 Overview 失败指标到 Logs → Request Drawer → Trace 的一条完整路径；从 Connect 测试请求到 Logs 的一条完整路径；从 Pricing 修改到差异确认与结果反馈的一条管理路径。
- 数据语义回归：缺失价格、精确费用、范围费用、失败 Attempt、已归档明细、未检测供应商，UI 不呈现误导值。

### 8.3 Definition of Done

- [ ] 所有 P0 视图完成对应功能验收，无明显回归。
- [ ] 同一指标在 Overview、Trends、Logs 和 Embed 中分母、时区与金额语义一致。
- [ ] 不存在「无数据」被默认为零、失败被默认为成功、未测速被默认为健康的情况。
- [ ] 所有破坏性/高影响 Admin 操作有确认与结果状态，且正确受权限控制。
- [ ] 390px 无页面级意外溢出；长列表在局部滚动或响应式详情中可访问。

## 10. 本文档的源码验证清单

在实现前逐项确认，不得把待验证事项作为已存在的后端 API：

- [ ] Dashboard 的请求状态、成本、缓存和 RTT 的字段口径。
- [ ] `usage_events` 明细与逻辑请求、Attempt、Trace 的关系。
- [ ] `pricing_overrides` 操作是否即时生效、是否热加载，以及 `PUT /api/pricing/:modelId` 的权限。
- [ ] `isolatedProviders: true` 时 Provider 启停与启动配置的关系。
- [ ] `traceId`、`spanId`、`parentSpanId`、时间戳的真实性、保留期与归档降级。
- [ ] SSE 增量协议、断线重连、更新时效语义。
- [ ] Embed 的权限模型、宿主反向代理、主题参数与容器尺寸策略。

**最终交付原则**：优先让 UI 准确解释 Model Infra Kit 已有的执行、计费与可靠性事实，再扩展管理和分析操作；不得为了展示功能而改变数据真义。
