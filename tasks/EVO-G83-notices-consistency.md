# EVO-G83 — 同一件事不应只在某一个命令里被说明

> 卡号 G83（P2）· 来源：对**已发布产物 0.2.23** 的独立再审计（`.tmp/audit-R232.md` 的 F7 / F8）
> 读卡前先读 `AGENTS.md` 与 `docs/interfaces.md`

## 一句话

产品在几个片子里陆续加了三样**解释性输出**，但它们各自只装进了**一个**命令——于是"同一批数据，换个命令看，就得不到解释"。

## 现状（均为产物实测）

1. **共享库提示只在 `usage summary`（F7）**：`usage summary` 会打「未指定 `--db`，本次读取的是默认共享库 `<路径>`」；而**同 cwd 下的 `usage logs` / `usage trends` 零提示**。用户从 `logs` 看到的数字**同样来自那个共享库**，却没有任何说明。
2. **标签可过滤但看不见（F8）**：`--tag` 过滤**生效**，但 `usage logs` **没有标签列**——用户筛完后**看不到自己筛的是什么**，也无法判断某行为何被包含/排除。

## 目标

让**同一批数据在任何命令里都带同样的解释**：
- 凡会在**同一个库**上给结果的命令，都应在**同一条件下**给出共享库提示（或明确说明"为什么这里不需要"）。
- `--tag` 生效的面，应能**看见**标签（表格列或等价输出）；若你判断不该加列，必须给出**用户可自查**的方式并说明理由。

## 不能破坏什么

- **不传 `--db` 时默认路径行为不变**；**显式 `--db` 时**仍按 G64 的裁定**完全静默**（连路径都不回显）。
- **G77 的折叠库提示与 G78 的成本下限表达不得回退**。
- `usage export` 的 **CSV 列** 属 G81 的范围，本卡**不要动 CSV**。
- 既有测试全绿；`tsc` 0；字典 zh/en 对等（键只能成对增删）。

## 验收标准

- **A1**：在**同一个共享库**上，`usage summary` / `logs` / `trends` 三者**都能**（或在报告中说明为何某者不需要）指出数据来自默认共享库。**给出三种命令的真实输出**。
- **A2**：显式 `--db` 时三者**仍完全静默**（反向断言，期望值来自外部：断言提示出现次数为 0 之外，还要断言输出行数与对照库一致）。
- **A3**：`--tag X` 过滤后，用户能**看见**该过滤与标签值（或报告说明替代方式并实测）。
- **A4**：全量测试在 **zh-CN** 与 `LC_ALL=en_US.UTF-8` 下均全绿；`typecheck` 0；`e2e` exit 0；`check-envs` 三环境 PASS。
- **A5（自检）**：新断言**改前必须能红**（G43）；指出**未覆盖**的分支（R208）。

## 风险提示

「不喧哗」是本项目的既有取向：**只在共享库这一事实成立时提示**，不要为了对齐而在所有命令里加噪声。若某命令**本该静默**（例如它已经显式接受了库参数），**说明理由即可**，不要强行凑齐三处。
