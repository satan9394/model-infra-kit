# EVO-G86 — CLI 面必须能把一行 CSV 对到一条 log

> 卡号 G86（P1，优先于 G85）· 来源：G81 的独立评审（`.tmp/eval-G81.md` 第 6 项）
> 读卡前先读 `AGENTS.md` 与 `docs/interfaces.md`

## 一句话

G81 给 `usage export` 补了 `request_id` 等 7 列，让**文件**可追溯；但 **CLI 的 `usage logs` 表不打印 id**——**本项目是 CLI 优先的工具，不跑 `serve` 的用户根本拿不到那条 id**。于是「一行 CSV 对一条 log」**在 CLI 面只完成了一半**。

## 现状（评审实测）

- `usage.ts` 全文件无 `requestId`；`usage logs` 表（约 `usage.ts:623`）不打印 id。
- 对齐可达路径只剩 `GET /api/usage/logs/:id`——**需要用户起服务**，而 `serve` 不是默认运行的东西。
- 毫秒级组合键（`ts` + `model` + …）对**同一毫秒内的重复调用不唯一**，所以不能靠组合键替代。

## 目标

**只用终端**的用户也能做到：从 `usage export` 的某一行拿到标识 → 在 `usage logs` 里定位到**同一条**记录。

**做法（你判断，二者皆可）**：给 `usage logs` 增加 **`--with-id`** 开关，或在表尾**默认**增一列 id。
- 若选**默认增列**：注意「既有行与顺序尽量不变」的取向，须在报告中说明取舍并更新契约。
- 若选**开关**：默认输出**逐字不变**（这是更保守的选择，也是编排者的倾向——但你可推翻，给理由）。

## 顺带修一处「自证」反模式

评审登记：`--out` / 空库相关用例（约 `test:401/614/619`）**用 `USAGE_CSV_HEADER` 与自身比较**——这**对表头漂移没有检测力**（同一常量既是被检验对象又是期望值，违反 R231）。
→ 请把这几处的期望值换成**外部字面量**（手打的表头串），或明确断言与一条独立来源一致。

## 不能破坏什么

- **`usage export` 的 22 列与前 15 列的字面量锁不变**（G81 刚建立）。
- **`usage logs` 的默认输出尽量逐字不变**；字典 zh/en 对等；`--json`（若有）不破坏。
- **金额仍以整数微美元为真源**。
- 契约（硬性规则 5）：若新增列/开关或改变输出，**同步 `docs/interfaces.md`**。
- 既有测试全绿；`tsc` 0。

## 验收标准

- **A1（端到端对齐）**：造 ≥2 条用量 → 从 `usage export` 取某行 `request_id` → **仅用 CLI**（`usage logs`，必要时加 `--with-id` 或新列）定位到**同一条**记录，并**断言两侧一致**。**改前必须能红**（贴出改前「CLI 面拿不到 id」的真实输出）。
- **A2（同毫秒不唯一）**：构造**同毫秒的两次调用**，断言你新增的标识**仍能区分**它们（这正是不用组合键的理由）。
- **A3（外部期望值）**：把上述 `USAGE_CSV_HEADER` 自证的用例改为**外部字面量**，并说明改前它为什么抓不到漂移（可临时改一个列名自证它会红，随后还原）。
- **A4**：`typecheck` 0；全量测试在 **zh-CN** 与 **`LC_ALL=en_US.UTF-8`+`LANG=en_US.UTF-8`** 下均全绿（**基线 670**，35 文件）；`e2e` exit 0；`check-envs` 三环境 PASS；字典对等。
- **A5（自检）**：新断言**改前必须能红**（G43）；报告指出**未覆盖**的分支（R208）；凡断言「没有 X」，期望值来自被检验对象之外（R231）。

## 错误场景

空库（无记录 → 不打印 id 列/开关下无输出变化）；`--limit` 截断时 id 仍正确；`--json` 路径一致。
