# EVO-G81 — 导出物必须可对账、不可注入

> 卡号 G81（P1）· 来源：对**已发布产物 0.2.23** 的独立再审计（证据见 `.tmp/audit-R232.md` 的 F4 / F5 / F6）
> 读卡前先读 `AGENTS.md`（硬性规则 + 复盘教训）与 `docs/interfaces.md`（CSV 与用量契约）

## 一句话

`usage export` 的 CSV 是**给机器对账用的**，但它现在**行和 ≠ 合计**、**缺关键列而对不上 logs**、且**标签值能改变行结构**。本卡让它成为一份**可对账、可追溯、不可注入**的产物。

## 用户场景

宿主把用量导出后与自己的账目、或与 `usage logs` / `usage logs/:id` 逐条核对；也可能把它回灌进另一个系统。任何"三处数字不一致"都会让使用者不再信任这套计量。

## 现状（三条独立缺陷，均已在 0.2.23/0.2.24 产物上实测）

1. **行和 ≠ 合计（F4）**：`usage summary --from 2026-09-12` 给 `0.0007`，而同 5 行 CSV 相加是 `0.0006`——因为**逐行只留 4 位小数**，微美元被丢弃。**对账必然失败。**
2. **缺可追溯列（F6）**：CSV 恰好 15 列（与契约一致），但没有 `request_id` / `session_id` / `first_token_ms` / `is_streaming` / `error_code` → **无法与 `logs` / `logs/:id` 对应**，也无法按幂等键回灌。
3. **标签可改变行结构（F5 的剩余面）**：G82 已在**渲染出口**把控制字符压平（`sanitizeTagForDisplay`），但**CSV 侧的完整性**要单独用断言钉住——请先核对 G82 之后是否仍有任何标签值能造成**单条记录跨物理行**；若有，在此修；若无，**写出断言把它锁死**。

## 目标

- **行和 == 合计**（在金额精度层面成立，且**仍以整数微美元为真相源**）。
- CSV 含**足以与 `logs` 对齐**的标识列；列只能**追加**，既有的 15 列**名称与顺序逐字不变**。
- **任何标签值都不能改变 CSV 的行结构**（单条记录恰好一行）。

## 不能破坏什么

- **金额仍以整数微美元累加**（硬性规则 2）；禁止 `SUM(CAST(cost AS REAL))`。
- **既有 15 列的列名与顺序逐字不变**（外部脚本按索引或表头读取）。新增列**只能追加在末尾**。
- **`usage summary` / `logs` / `trends` 的既有行与顺序**尽量不变。
- **契约必须同步**（硬性规则 5）：CSV 列变更、任何新增字段，都要更新 `docs/interfaces.md`，并**用 `dist` 实际产物核对**（注意区分值导出与纯类型导出——纯类型在 `.mjs` 里 0 命中是必然）。
- 既有测试全绿（当前基线见 `AGENTS.md`「当前状态」）；`tsc` 0；字典 zh/en 对等。

## 验收标准

- **A1（对账）**：构造若干条用量（**含未定价与已定价混合**），断言 `usage export` 各行金额之和 **==** `usage summary` 给出的合计（在声明的一致精度下）。**改前必须能红**（贴出改前那个 0.0006 vs 0.0007 形状的真实输出）。
- **A2（可追溯）**：CSV 中能按标识列定位到 `usage logs` 的同一行；断言至少一个真实标识（如 `request_id`）在两侧一致。若你判断某列不该加，**说明理由并登记**，但必须回答"用户如何把一行 CSV 与一条 log 对上"。
- **A3（不可注入）**：构造**含换行/控制字符**的标签值 → 断言 CSV 记录数不因标签而增加（**期望值来自外部**：行数 == 表头 1 + 事件数，另跑 benign 基线对照），且 `--by-tag` 不出现伪造行。
- **A4（契约）**：`docs/interfaces.md` 已更新；新增列的**类型与语义**在文档里可查。
- **A5**：`pnpm --filter model-infra-kit typecheck` → 0；全量测试在 **zh-CN** 与 **`LC_ALL=en_US.UTF-8`+`LANG=en_US.UTF-8`** 下均全绿；`node scripts/e2e/run.mjs` exit 0；`node scripts/check-envs.mjs` 三环境 PASS。
- **A6（自检）**：每条新断言**改前必须能红**（G43）；报告里指出验证**真正走到了哪条新分支**、哪条**没覆盖**（R208）；凡断言"没有发生 X"，期望值必须来自被检验对象之外（R231）。

## 错误场景

- **标签值极长 / 含引号 / 含逗号 / 含 CRLF**：CSV 引号规则必须仍然成立（记录不跨行、字段不串位）。
- **空库导出**：仍是一行表头，无数据行。
- **`--from/--to` 边界**：导出与 summary 的口径必须一致（G79 已引入范围说明，勿回退）。

## 测试要求

- 新断言锚在**产物级**行为上（本项目铁律：涉及平台/精度/契约的改动以 CI 为准）。
- 若新增列，**必须有字面量断言**锁住"前 15 列名与顺序逐字不变"。
- **不要**为跑通而对既有断言放宽——若某条既有断言**断言的是缺陷值**，按 G82 的处置方式：**逐项申报 + 保留旧值字面量**。
